# review/ — 子 agent 审查记录

- **目录层级**：一级子目录按审查对象划分（常见：数据处理 / 算法实现 / 结果生成，其他部分按需创建）；文件名 `YYYY-MM-DD_序号_状态.md`（序号递增，不覆盖历史）。
- **状态三态**：`通过`（无问题）/ `未修复`（有问题未改）/ `已修复`（问题已改）——**文件名后缀 + 文件头部显著标记双保险**；问题修复后更新记录内容并重命名文件（`_未修复` → `_已修复`）。
- **文件内容**：审查对象（哪一部分、涉及脚本/结果文件）、审查时间、审查发现（逐条：问题、证据、AI 幻觉拟合嫌疑）、处置（通过 / 修复内容 / 是否复审）。
- 审查流程见 CLAUDE.md「生信算法脚本规范」节。

## 记录文件模板

```
# 审查记录：<审查对象>（<日期>，第 <N> 次）

> 审查状态：【未修复】   ← 通过 / 未修复 / 已修复，醒目标注
> 审查方式：独立子 agent（不依赖工作记录与注释）

## 审查对象
<哪一部分、涉及脚本/结果文件路径>

## 审查发现
<逐条列出：问题、证据、是否 AI 幻觉拟合嫌疑>

## 处置
<通过 / 需修复；修复内容；是否复审>
```
